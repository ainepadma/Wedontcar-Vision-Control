# Wedontcar-Vision-Control

智能车竞赛镜头组 RT1064 固件。MT9V034 图像采集、白色赛道识别、PD 转向、双轮 PI 调速，以及 270° / 360° 环岛视觉补线与七条纹锁停。

当前版本 **0.33.0**（2026-11-10），开发分支 `1110-deng`，基于该分支提交 `ca9d664`。发布提交标题为 **平滑360**。版本与算法变化见 [CHANGELOG](CHANGELOG.md)，接手顺序见 [SUMMARY](SUMMARY.md)，协作规则见 [COLLABORATORS](COLLABORATORS.md)，实车验收清单见 [待测试](待测试.md)。

本版整理 0.30.0～0.32.0 的入环切线、第三次补线稳定性和绿线向内弯改动，并加入左环岛 S3/S4、S5/S6 的普通白路中线续接。蓝线修补缺边，已有近端绿线保留，前方同一条白路继续按普通循迹结果计算中线，接好的路径共同参与偏差与航向控制。单帧照片和离线回放的结论均按实际验证范围记录。

**默认配置为 `RING_FEATURE_ENABLED=1`，启用 270° / 360° 环岛识别。C14 视觉与环岛保护上电关闭，C15 每次有效按下将普通档直道目标增加 10。** 普通行驶 PWM 上限为 7000，七条纹位置保持上限为 2500。当前条纹到位高度阈值为图高的 23%。

## 工程与数据流

```text
demo/user/src/       11 个应用 .c 与 2 个被包含的 .inc
demo/user/inc/       板级配置、算法接口、功能开关
demo/mdk/            Keil 工程，目标 nor_sdram_zf_dtcm
demo/iar/            历史 IAR 工程，本版未验证
libraries/           逐飞 RT1064 库、NXP SDK、设备驱动
tools/               主机测试、图像夹具、图像采样与日志导出脚本
docs/                当前专项说明与按版本保留的历史验证记录
```

| 文件 | 维护职责 |
| --- | --- |
| `main.c` | 外设初始化、冻结取帧、双翻转、预处理、视觉调用、预览与诊断 |
| `img_process.c/.h` | 自适应阈值、局部补偿、参数平滑、小黑孔与孤立点清理 |
| `track_vision.c/.h` | 普通白路中线、近端路线关联、环岛接口及左环白路续接 |
| `track_near_route.inc` | 从近端可见道路播种，限制可连接的白色路线 |
| `ring_corner.c/.h` | 八邻域轮廓、角点、270° / 360° 候选补线与中线几何 |
| `ring_control.c/.h` | 类型与方向锁定、视觉阶段、候选选择、短时保持、出环与重入 |
| `track_control.c/.h` | 启停、图像有效性、PD、滤波、舵机限速与基础速度 |
| `isr.c` | 10 ms 控制中断、C12–C15、观测邮箱、反馈保护和最终执行 |
| `pid.c/.h` | 独立双轮 PI、输出限幅、加速斜坡与转角差速 |
| `imu_navigation.c/.h` | 100 Hz IMU 采样后的坐标映射、零偏与角速度 |
| `track_stripe_brake.c/.h` | 七条纹识别、准备与锁停、双轮位置保持 |
| `steering_log.c/.h` | 1 MiB 环形转向记录、冻结与停车后 CSV 导出 |

`.inc` 随源码保留，由现有 C 文件包含。`ring_360_zore.inc` 是留存的旧实现，当前环岛几何入口是 `ring_corner_process()`。工程以仓库内源文件和相对路径为准。Objects、Listings、个人 IDE 状态和本地 firmware 副本受 `.gitignore` 排除。

数据流为 CSI 帧 → 独立副本与帧号复核 → 上下 / 左右双翻转 → 稳定预处理 → 普通视觉 → 环岛候选与中线续接 → 同帧邮箱 → 10 ms 控制中断 → PD 与差速目标 → 双轮 PI → PWM。七条纹独立检测，到位锁存后进入位置保持分支。

## 当前算法

### 图像与路线

- 摄像头输出 304×154 窗口、2×2 合并、50 FPS 配置，曝光 1024、增益 64。实际采集、处理和显示帧率分别以 `CFPS/PFPS/DFPS` 为准。
- 传感器已裁切视野，当前 `vision_geometry.h` 使用整个交付窗口，搜索与普通视觉为 `[0%H, 100%H)`，近端播种从 66%H 开始。
- 预处理使用 4×3 分块、白权重 42%、局部强度 50%、参数平滑时间常数 25 ms，以及孤立点和小黑孔处理。仅保留阈值等参数，当前像素独立计算。
- 普通视觉先执行严格白段提取，再以近端关联补回可见主白路。白段宽度、密度、重叠与像素连接共同约束路线，触边急弯可走主白带恢复。
- 左环岛 S3/S4、S5/S6 在已有补线中线的远端继续读取普通视觉行中心。新增点须能从原路线逐段穿过白色像素，最多跨过两行普通检测漏行；已验证的白段会插值补齐。
- 续接保留已有蓝线及中线采样点，排除黑色隔离带后的道路，并限制上方直行或右支路通过宽白区抢线。接好的中线重新计算实际控制 `E/H`。右环岛仍使用原流程，其对应改进列入待验收。

### 270° 与 360° 环岛

| 场景 / 内部阶段 | 当前行为 |
| --- | --- |
| 270° | 入口双侧角点连接，恢复普通路后进入环内；下一处有效双侧开口作为出口，恢复道路后完成 |
| 360° S1 | 维持 A–P 入口补线 `G09/G10`，等待上方入环尖角 |
| 360° S2 | 保留的旧 PREIN 编号；当前常规入环从 S1 直接进入 S3 |
| 360° S3/S4 | 第二次补线，`G13/G14` 与 `G15/G16`；左环可继续接普通白路中线 |
| 360° S5/S6 | 第三次补线，`G17/G18` 与 `G19/G20`；从外侧近端试角、跟踪同角并记录分隔带 |
| 360° S7 | 第四次补线 `G21/G22`；连续三个新帧看不到出口尖角后完成，进入冷却 |
| 360° 冷却 | 至少 600 ms 且连续 10 个可信、对齐的普通道路帧后重新允许入口识别 |

环岛完成数量用于记录，重新允许识别后可通过下一处环岛。冷却、270° 类型优先级和锁定中的类型会影响下一处入口，诊断时同时记录 `FW/RT/RS/CS/CG`。S7 当前采用出口尖角消失三帧的完成方式，0.29.0 的两帧普通道路与 8 帧 / 200 ms 解除限速条件属于历史版本。

| 参数 | 源码初值 | 含义与调节 |
| --- | --- | --- |
| `ring_entry_v_min_y_percent` | `20` | 上方入环尖角最低行位，从图顶量百分比；提高会推迟切线 |
| `ring_entry_v_pull_frames` | `1` | 切到 S3 所需连续有效新帧，约束在 1～3 |
| `ring_third_left_lean` | `0.26` | 第三次蓝线内倾，约束在 0～0.50；改变蓝线会影响中线有效性 |
| `ring_third_left_center_shift` | `0.45` | 左环第三次绿线最大内移占图宽比例，约束在 0～0.65；可按 0.05 调节 |

两个浮点参数位于 `ring_corner.c`，入环参数位于 `ring_control.c`，均可通过 Keil Watch 临时修改，复位后恢复源码初值。绿线远端在同一段白路内收住，接近黑边后继续加大参数可能不再产生位移。

### 转向与速度

- PD 为 `KP=0.030`、`KD=0.0005`。远航向权重 0.40、接近阶段 0.05、近航向权重 0.80。实际控制沿用滤波、微分与舵机变化率限制。
- 舵机右 / 中 / 左指令为 74° / 87° / 100°，C30、50 Hz，变化率 180°/s。软件指令角需结合机械标定解释。
- 普通档直道 / 弯道最低为 120 / 90 计数每 10 ms。FULL 宏保留 253 / 145，当前 C15 执行普通直道目标加 10。
- 差速为 `delta = target × 0.4 × tan(转角)`，单轮增减限公共目标的 50%。
- 双轮 PI 为 P=25、I=0.3、D=0，积分状态限 12000，普通行驶 PWM 为 0～7000。条纹位置保持独立使用 PWM 上限 2500。

### 按键、启动与保护

| 按键 | 功能 | 上电默认 |
| --- | --- | --- |
| C12 | 屏幕与 USB 图传开关 | 开启 |
| C13 | 整车启动 / 停止；成功启动新一趟日志 | 停止 |
| C14 | 视觉与环岛自动停车保护 | 关闭 |
| C15 | 每次有效按下给普通直道目标加 10；长按一次 | 普通目标 120 |

保护开启时，启动要求连续 3 个有效观测、置信度至少 45；连续 3 帧失效或超过 150 ms 未更新等条件可触发停车。C14 关闭时图像失效仍降到弯道最低目标。编码器反号、无反馈、超速和七条纹锁停独立生效。

七条纹连续 3 个可靠新帧进入 ARMED，到位的新帧可立即锁停。当前底沿阈值为 92%H、高度阈值为 23%H；锁存后的裁切证据、舵机保持和双轮位置保持见 [条纹刹车说明](docs/STRIPE_BRAKE.md)。C13 无法解除条纹锁停，主板复位或重新上电清除。

1. 安装 Keil MDK 5、Arm Compiler **6.19** 与 `NXP.MIMXRT1064_DFP.25.09.00`。库和 SDK 随仓库提供。
2. 打开 `demo/mdk/rt1064.uvprojx`，选择 `nor_sdram_zf_dtcm`，执行 Rebuild。
3. 正常工程输出为 `demo/mdk/Objects/rt1064.axf`。本地隔离构建输出到 `Objects/local-build-*`，以构建日志打印的目录为准。IAR 工程尚未接入完整新增模块，本版未验证。
4. 烧录后确认 `#CAM FW=0.33.0`，记录 C14 状态、C15 加速次数和实际 `TARGET10`，再按 [待测试](待测试.md) 验收。本次发布未执行烧录。

```powershell
python tools/build_keil_local.py --uv4 C:/Keil_v5/UV4/UV4.exe
```

USB 图传默认发送冻结原始灰度图（`CAMERA_SEND_RAW=1`）。屏幕显示二值图及同帧叠加，显示分辨率 125×100、刷新周期 100 ms。二者通过同一双翻转方向对应。

| 诊断字段 | 含义 |
| --- | --- |
| `CAP/VF/PROC/DISP`、`CFPS/PFPS/DFPS` | 帧号、计数及采集 / 处理 / 显示帧率 |
| `MOTOR/PROTECT/FULL/READY/STOP` | 运行、保护、档位、就绪和停车原因 |
| `TRACK/Q/VR/N/F/REJ` | 路径有效性、置信度、覆盖与拒绝原因 |
| `ERR/HEAD/SERVO10/TARGET10` | 实际所选路径偏差、航向、舵机和目标速度×10 |
| `RT/RS/CS/CG/HOLD/AP/AR` | 类型、粗阶段、视觉细阶段、补线编号、保持与出口状态 |
| `LSPD/RSPD/LPWM/RPWM` | 两轮反馈和 PWM 幅值 |
| 屏幕 `C/P`、`N/G/H/U` | 实际控制 / 停机预览，普通 / 补线 / 保持 / 无效来源 |

`FW=0.33.0` 为版本字符串，同一诊断行后面的整数 `FW=` 沿用远端宽度字段。停车后可用 `tools/export_steering_log.py` 导出 33 列 CSV，流程见 [转向日志](docs/STEERING_LOG.md)。

## 接手修改的顺序

1. 获取 `1110-deng`，核对 `version.yml`、三个固件版本输出和环岛开关，再读 SUMMARY 与当前专项文档。
2. 运行当前主机入口并保留结果，复现历史失败时按所属版本的说明区分接口和断言。
3. 图像问题看 `img_process`，普通中线及白路续接看 `track_vision.c`，补线几何与参数看 `ring_corner.c`，状态选择看 `ring_control.c`，转向与轮速分别看 `track_control.c` / `pid.c`。
4. 每次修改后同步版本、更新日志、阶段总结和相关专项文档，记录实际编译与实车结果，再通过 PR 合并。
