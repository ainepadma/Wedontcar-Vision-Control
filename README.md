# Wedontcar-Vision-Control

智能车竞赛镜头组 RT1064 固件。MT9V034 图像采集、白色赛道识别、PD 转向、双轮 PI 调速，以及 270° / 360° 环岛视觉补线与七条纹锁停。

## 项目背景

本项目用于智能车竞赛镜头组。RT1064 根据摄像头识别出的赛道中线控制转向和双轮速度，并在环岛缺边时通过视觉补线生成行驶路线。

## 当前状态

当前版本 **0.38.0**（2026-11-10）修复左右 360° 环岛 S3 切换 S4 时的外侧尖角识别。上电时先采集陀螺仪静止零偏，再启用 C13 启停。实车反馈 270° 与 360° 入口混判，复现条件见更新日志。版本与算法变化见 [CHANGELOG](CHANGELOG.md)，接手顺序见 [SUMMARY](SUMMARY.md)，协作规则见 [COLLABORATORS](COLLABORATORS.md)，实车验收清单见 [待测试](待测试.md)。

本版整理 0.30.0～0.32.0 的入环切线、第三次补线稳定性和绿线向内弯改动，并加入左右环岛 S5/S6 的普通白路中线续接。蓝线修补缺边，已有近端绿线保留，前方同一条白路继续按普通循迹结果计算中线，接好的路径共同参与偏差与航向控制。单帧照片和离线回放的结论均按实际验证范围记录。

**默认配置为 `RING_FEATURE_ENABLED=1`，启用 270° / 360° 环岛识别。C14 视觉、环岛与七条纹停车保护上电关闭，C15 每次有效按下将普通档直道目标增加 10。** 普通行驶 PWM 上限为 7000，七条纹位置保持上限为 2500。当前条纹到位高度阈值为图高的 23%。

## 工程结构

### 工程与数据流

```text
demo/user/src/       11 个应用 .c 与 2 个被包含的 .inc
demo/user/inc/       板级配置、算法接口、功能开关
demo/mdk/            Keil 工程，目标 nor_sdram_zf_dtcm
demo/iar/            历史 IAR 工程，本版未验证
libraries/           逐飞 RT1064 库、NXP SDK、设备驱动
tools/               主机测试、图像夹具、图像采样与日志导出脚本
```

| 文件 | 维护职责 |
| --- | --- |
| `main.c` | 外设初始化、冻结取帧、双翻转、预处理、视觉调用、预览与诊断 |
| `img_process.c/.h` | 自适应阈值、局部补偿、参数平滑、小黑孔与孤立点清理 |
| `track_vision.c/.h` | 普通白路中线、近端路线关联、环岛接口及左右环白路续接 |
| `track_near_route.inc` | 从近端可见道路播种，限制可连接的白色路线 |
| `ring_corner.c/.h` | 八邻域轮廓、角点、270° / 360° 候选补线与中线几何 |
| `ring_control.c/.h` | 类型与方向锁定、视觉阶段、候选选择、短时保持、出环与重入 |
| `track_control.c/.h` | 启停、图像有效性、PD、滤波、舵机限速与基础速度 |
| `isr.c` | 10 ms 控制中断、C12–C15、观测邮箱、反馈保护和最终执行 |
| `pid.c/.h` | 独立双轮 PI、输出限幅、加速斜坡与转角差速 |
| `imu_navigation.c/.h` | 100 Hz IMU 采样后的坐标映射、零偏与角速度 |
| `track_stripe_brake.c/.h` | 七条纹识别、准备与锁停、双轮位置保持 |
| `steering_log.c/.h` | 1 MiB 环形转向记录、冻结与停车后 CSV 导出 |

`.inc` 随源码保留，由现有 C 文件包含。`ring_360_zore.inc` 是留存的旧实现，当前环岛几何入口是 `ring_corner_process()`。工程以仓库内源文件和相对路径为准。Objects、Listings、个人 IDE 状态和本地 firmware 副本受 `.gitignore` 排除。

数据流为 CSI 帧 → 独立副本与帧号复核 → 上下 / 左右双翻转 → 稳定预处理 → 普通视觉 → 环岛候选与中线续接 → 同帧邮箱 → 10 ms 控制中断 → PD 与差速目标 → 双轮 PI → PWM。七条纹独立检测，到位锁存后进入位置保持分支。

## 功能说明（v0.38.0）

### 当前算法

0.38.0 以普通白路或视觉补线生成控制中线，按键保护、转向和速度配置见以下各项。

### 1. 图像采集与预处理

- 摄像头输出 304×154 窗口、2×2 合并、50 FPS 配置，曝光 1024、增益 64。实际采集、处理和显示帧率分别以 `CFPS/PFPS/DFPS` 为准。
- 传感器已裁切视野，当前 `vision_geometry.h` 使用整个交付窗口，搜索与普通视觉为 `[0%H, 100%H)`，近端播种从 66%H 开始。
- 预处理使用 4×3 分块、白权重 42%、局部强度 50%、参数平滑时间常数 25 ms，以及孤立点和小黑孔处理。仅保留阈值等参数，当前像素独立计算。

### 2. 赛道识别

- 普通视觉先执行严格白段提取，再以近端关联补回可见主白路。白段宽度、密度、重叠与像素连接共同约束路线，触边急弯可走主白带恢复。
- 左右环岛 S5/S6 在已有补线中线的远端继续读取普通视觉行中心。新增点须能从原路线逐段穿过白色像素，最多跨过两行普通检测漏行；已验证的白段会插值补齐。
- 续接保留已有蓝线及中线采样点，排除黑色隔离带后的道路，并限制上方直行或右支路通过宽白区抢线。接好的中线重新计算实际控制 `E/H`。右环采用镜像续接，实车效果待验证。

### 3. 转向控制

- PD 为 `KP=0.030`、`KD=0.0007`。远航向权重 0.40、接近阶段 0.10、近航向权重 0.80。实际控制沿用滤波、微分与舵机变化率限制。
- 舵机右 / 中 / 左指令为 74° / 87° / 100°，C30、50 Hz，变化率 180°/s。软件指令角需结合机械标定解释。

### 4. 速度与差速

- 普通档直道 / 弯道最低为 120 / 90 计数每 10 ms。FULL 宏保留 253 / 145，当前 C15 执行普通直道目标加 10。
- 差速为 `delta = target × 0.4 × tan(转角)`，单轮增减限公共目标的 50%。
- 双轮 PI 为 P=25、I=0.3、D=0，积分状态限 12000，普通行驶 PWM 为 0～7000。条纹位置保持独立使用 PWM 上限 2500。

### 5. 按键与启停

| 按键 | 功能 | 上电默认 |
| --- | --- | --- |
| C12 | 屏幕与 USB 图传开关 | 开启 |
| C13 | 整车启动 / 停止；成功启动新一趟日志 | 停止 |
| C14 | 视觉、环岛与七条纹自动停车保护 | 关闭 |
| C15 | 每次有效按下给普通直道目标加 10；长按一次 | 普通目标 120 |

保护开启时，启动要求连续 3 个有效观测、置信度至少 45；连续 3 帧失效或超过 150 ms 未更新等条件可触发停车。C14 关闭时图像失效仍降到弯道最低目标。编码器反号、无反馈和超速保护独立生效。七条纹停车由 C14 控制。

C14 开启时七条纹连续 3 个可靠新帧进入 ARMED，到位的新帧可立即锁停。当前底沿阈值为 92%H、高度阈值为 23%H；锁存后的裁切证据、舵机保持和双轮位置保持见 [条纹刹车说明](#七条纹锁停)。C13 无法解除条纹锁停，主板复位或重新上电清除。

### 6. IMU 与偏航角速度

开机显示 `IMU CAL: STILL` 时保持车身静止。固件复用历史版本的 200 个有效 GY 样本平均法，通常约 2 秒完成校准，然后启用 C13；若传感器连续未就绪，最多等待 3 秒再继续启动。串口 `IB=1`、`IBS=200` 表示本次零偏已就绪，随后按 10 ms 周期采样。

### 7. 环岛状态机

| 场景 / 内部阶段 | 当前行为 |
| --- | --- |
| 270° | 入口双侧角点连接，恢复普通路后进入环内；下一处有效双侧开口作为出口，恢复道路后完成 |
| 360° S1 | A–P 入口补线 `G09/G10`，确认 A 消失、P 与对侧边界等条件 |
| 360° S2 | P 点连接画面底部，确认内侧 V、P 消失与对侧连续后进入 S3 |
| 360° S3/S4 | 第二次补线，`G13/G14` 与 `G15/G16`；恢复 0.29 的顶点裁剪 |
| 360° S5/S6 | 第三次补线，`G17/G18` 与 `G19/G20`；从外侧近端试角、跟踪同角并记录分隔带 |
| 360° S7 | 第四次补线 `G21/G22`；连续三个新帧看不到出口尖角后完成，进入冷却 |
| 360° 冷却 | 至少 600 ms 且连续 10 个可信、对齐的普通道路帧后重新允许入口识别 |

环岛完成数量用于记录，重新允许识别后可通过下一处环岛。冷却、270° 类型优先级和锁定中的类型会影响下一处入口，诊断时同时记录 `FW/RT/RS/CS/CG`。S7 当前采用出口尖角消失三帧的完成方式，0.29.0 的两帧普通道路与 8 帧 / 200 ms 解除限速条件属于历史版本。

| 参数 | 源码初值 | 含义与调节 |
| --- | --- | --- |
| `ring_third_left_lean` | `0.26` | 第三次蓝线内倾，约束在 0～0.50；改变蓝线会影响中线有效性 |
| `ring_third_left_center_shift` | `0.55` | 左右环第三次绿线最大内移占图宽比例，约束在 0～0.65；可按 0.05 调节 |

两个浮点参数位于 `ring_corner.c`，均可通过 Keil Watch 临时修改，复位后恢复源码初值。绿线远端在同一段白路内收住，接近黑边后继续加大参数可能不再产生位移。

## 使用指南

### 1. 环境准备

安装 Keil MDK 5、Arm Compiler **6.19** 与 `NXP.MIMXRT1064_DFP.25.09.00`。库和 SDK 随仓库提供。

### 2. 编译

#### 编译与调试

1. 打开 `demo/mdk/rt1064.uvprojx`，选择 `nor_sdram_zf_dtcm`，执行 Rebuild。
2. 正常工程输出为 `demo/mdk/Objects/rt1064.axf`。本地隔离构建输出到 `Objects/local-build-*`，以构建日志打印的目录为准。IAR 工程尚未接入完整新增模块，本版未验证。
3. 烧录后确认 `#CAM FW=0.38.0`，记录 C14 状态、C15 加速次数和实际 `TARGET10`，再按 [待测试](待测试.md) 验收。本地 0.38.0 下载尝试失败，需在板上核对版本。

```powershell
python tools/build_keil_local.py --uv4 C:/Keil_v5/UV4/UV4.exe
```

### 3. 烧录

1. 将 CMSIS-DAP 调试器连接目标板的 SWD 接口，给目标板供电。
2. 在 Keil 中执行 Download（F8），等待日志显示 `Verify OK`。
3. 启动后核对串口输出 `#CAM FW=0.38.0`。

### 4. 上电与启动

1. 上电后将车放在赛道上，检查屏幕上的道路边界和中线。
2. 若已用 C14 开启视觉保护，等待连续 3 个有效观测、置信度至少 45。
3. 短按 C13 启动，再次短按 C13 停车。

### 5. 按键操作

C12 切换屏幕与图传，C13 控制启停，C14 切换视觉、环岛与七条纹停车保护，C15 每次有效按下将普通档直道目标加 10。各键上电默认值见[按键与启停](#5-按键与启停)。

### 6. 屏幕显示

当前屏幕用红色显示观测边界、蓝色显示补线、绿色显示中线。

### 7. 串口诊断

USB 图传默认发送冻结原始灰度图（`CAMERA_SEND_RAW=1`）。屏幕显示二值图及同帧叠加，显示分辨率 125×100、刷新周期 100 ms。二者通过同一双翻转方向对应。

| 诊断字段 | 含义 |
| --- | --- |
| `CAP/VF/PROC/DISP`、`CFPS/PFPS/DFPS` | 帧号、计数及采集 / 处理 / 显示帧率 |
| `MOTOR/PROTECT/FULL/READY/STOP` | 运行、保护、档位、就绪和停车原因 |
| `TRACK/Q/VR/N/F/REJ` | 路径有效性、置信度、覆盖与拒绝原因 |
| `ERR/HEAD/SERVO10/TARGET10` | 实际所选路径偏差、航向、舵机和目标速度×10 |
| `RT/RS/CS/CG/HOLD/AP/AR` | 类型、粗阶段、视觉细阶段、补线编号、保持与出口状态 |
| `LSPD/RSPD/LPWM/RPWM` | 两轮反馈和 PWM 幅值 |

#### 环岛诊断

适用当前实验分支 `1110-ainepadma`。当前参数以源码和 README 为准，各版原始记录见 CHANGELOG。

##### 屏幕与串口

- `P` 表示停机手推预览，`C` 表示实际控制；屏幕下方更近，上方更远。
- `N` 为普通路径，`G` 为补线路径，`H` 为最多 120 ms 的补线保持，`U` 为无有效控制路径。`?` 可表示控制与显示帧未对齐。
- `E/H` 为控制所选路线的横向偏差与航向。`G00` 表示当前没有选补线编号，需结合 N/U 判断普通路径是否可用。
- `A0/A1` 对应出口分隔 / 解锁状态，需结合源码字段解释；其含义与角点名称 A 分开。
- 串口对齐 `FW/RT/RS/CS/CG/CVF/CGF/HOLD/AP/AR`。当前固件三处版本标识为 `FW=0.38.0`。

##### 四次补线与七阶段

| 内部阶段 | 左 / 右环编号 | 当前用途 |
| --- | --- | --- |
| S1 ENTRY | G09 / G10 | 第一条入口 A–P 线 |
| S2 PREIN | G11 / G12（旧几何保留） | P 点连接画面底部，随后进入 S3 |
| S3 INLOCK | G13 / G14 | 第二条线，目标上方尖角至对侧真实底端 |
| S4 JOIN | G15 / G16 | 第二条线的外侧角接续；连续两个新帧确认同一个真实外侧 V 和有效补线后进入 |
| S5 RING | G17 / G18 | 第三条线，外侧近端角至真实上边界 |
| S6 EXITWAIT | G19 / G20 | 记录分隔后继续第三条线并等第四条 |
| S7 EXIT | G21 / G22 | 第四条线，出口内侧角至同侧实际底边 |

左环内侧为图像左侧。照片中的 S4/G15 属于第二次补线的后半段。270° 的 S2 则表示环内普通循迹，必须结合 RT 区分。

##### 入环与第三线参数

| 参数 | 当前源码初值 | 约束 |
| --- | --- | --- |
| `ring_third_left_lean` | 0.26 | 蓝线内倾 0～0.50，左右镜像旋转 |
| `ring_third_left_center_shift` | 0.55 | 左右第三线绿线内移 0～0.65，近端三分之一固定 |

S1、S2 与 S3 按 0.29 的入口判据逐级切换。第三次补线按外侧边界从近到远试角，优先跟住同一角。蓝线倾斜会影响近端中线是否仍在白路上，绿线内移受同一白色连续段约束。

##### 普通白路续接

当前在 `track_ring_vision_process()` 完成几何稳定后，为左右环 S5/S6 接入普通视觉 `center/row_valid`。保留已有补线和中线采样点，从最远有效点向前检查白色连接，限制跳变和错误右支。像素全白的短检测漏行可补齐，新增路线重新计算控制 E/H。

S3/S4 仍裁去蓝线顶点以上区域。S5/S6 沿连通白路续接，`active_top` 表示本帧实际支持范围；黑带和错误上方直支仍被拒绝。屏幕和控制使用同一个 guide 的续接结果，原普通输出也继续保留。

##### 第三线通过、出环与下一圈

1. 第三线用过后记录分隔带，分隔带当帧维持第三线。
2. 分隔带已离开、第三线连续缺失至少 3 帧且 120 ms 保持过期，才锁存第三线通过。
3. 随后连续 3 个新帧确认同侧出口尖角及有效第四线。允许的帧间位置差为图宽 8%、图高 12%。
4. S7 出口角连续缺失 3 帧后完成，回普通循迹并进入冷却。该完成方式来自 `4fa227e` 的分支改动。
5. 360° 冷却至少 600 ms，并获得连续 10 帧可信、对齐的普通道路，才重新识别入口。环岛次数只有统计用途。

0.29.0 的 S7 两帧普通道路接管及 8 帧 / 200 ms 稳定释放属于历史行为。当前类型锁定后继续同一事件，270° 双侧开口在入口判断中优先；识别下一处入口时需同时排查类型和冷却。

#### 停车诊断

适用 `1110-ainepadma`。固件输出 `FW=0.38.0`。本版普通白路续接后的实际 E/H 和来源继续进入原控制器和转向日志。

| 原因 | 编号 | 当前解释 |
| --- | --- | --- |
| NONE / MANUAL / NOT_READY | 0 / 1 / 2 | 无故障、手动停止、保护开启时未就绪 |
| LOST / STALE | 3 / 4 | 连续失效或图像过期；受 C14 视觉保护开关控制 |
| ENCODER / NO_FEEDBACK / OVERSPEED | 5 / 6 / 7 | 编码器反号、无反馈、超速，独立于 C14 |
| RING | 8 | 环岛超时 / 失效保护 |
| STRIPE | 9 | 七条纹主动锁停，复位清除，C13 不能解除 |

上电 C14 默认关闭，编码器三类保护继续生效。`LAST` 保存触发前快照，CSV 中普通停机末条可已归零；条纹保持 PWM 可非零且只记录幅值。分析卡顿时对齐 `CS/CG`、N/G/H/U、E/H、servo10 和 frame_age_ms。

#### 七条纹锁停

C14 上电默认关闭。开启 C14 后才会累计七条纹识别并允许锁停；关闭 C14 会清除尚未锁停的准备状态。已经锁停时，关闭 C14 不解除位置保持，复位或重新上电清除。

只在原 0.27.0 工程接入条纹停车，没有迁移工程，没有修改循迹、环岛、相机预处理、速度档位或正常行驶 PID 参数。

当前采用本地工程已有的 `STRIPE_BRAKE_HEIGHT_PERCENT=23U`，历史 0.27/0.28 为 28%。底沿 92%、准备 3 帧、位置保持 12/35 与 PWM 2500 沿用现有实现。23% 调参的物理停车位置仍待复测。

当前主机检测与 ISR 模拟检查结果见 [0.33.0 验证](CHANGELOG.md#发布验收明细)，历史来源见 [0.28 合并说明](CHANGELOG.md#合并来源与交付记录)。

##### 手推验证

1. 重新上电或按主板复位键，开启 C14 保护后手推测试。
2. 从 P1/P2 的远处手推靠近条纹。三个新的可靠图像帧确认完整七条后，显示 `STRIPE ARMED`。
3. 关闭 C14 会清除尚未锁停的 ARMED 状态，重新开启后需重新确认三帧。
4. 一张可靠新帧满足 P4 的大小与底部位置即锁停，不再要求两帧到位。若确认 ARMED 的第三帧本身已到 P4，该帧直接锁停。
5. 屏幕显示 `LAST STRIPE`、`LOCKED RESET`，停车原因编号为 9。手推测试即使从未启动电机也会保存 LAST 记录。
6. 锁停后，左右轮每 10ms 独立读取编码器，输出抵抗位移与速度的正/反向力矩；舵机持续保持触发瞬间的指令角度。C13 不能解除锁停，目标速度保持零；相机停止更新也继续保持。
7. 主板复位或断电重启清除锁存，恢复原有待机状态；电机仍须按原流程按 C13 才正常行驶。

##### 到位与裁切

- 直接 P4 条件沿用照片对应的初始标定：条纹下沿达到图像高度的 92%，可见高度达到 23%。当前为 304×154 图像。
- ARMED 后已经确认条纹达到足够高度，就记住这份大小证据。当条纹移到画面底边、可见高度被裁短时，只要仍有跨行连续的成组条纹，就可以触发；不再用被裁短的当前高度否定已确认的接近过程。
- 首次准备仍要求完整七条、连续三个新帧；准备后的接近允许成组五/六条。不可靠、重复时间戳、过期观测不能凑准备票数或触发到位。
- 普通赛道检测是否有效不影响独立条纹检测；舵机标定模式和架空速度调试模式不启用本模块。

##### 保持力

锁轮为带限幅的编码器位置保持，参数仅位于 `demo/user/inc/track_stripe_brake.h`：位置增益 12，速度阻尼 35，PWM 上限 2500（满量程 10000 的 25%）。正常行驶的 PID 和 PWM 上限保持原值。

软件需要感知微小编码器位移后施加抵抗力，保持力取决于电机、驱动供电和轮胎抓地力；不能仅凭主机测试保证外力下车轮完全零位移。上述参数需要通过实际手推确认，尚未实车标定，也未验证长时间保持时的驱动/电机温升。

#### 转向日志与CSV导出

本功能记录转向控制数值。来源 0=N、1=G、2=H、3=U；旧 CSV 的 4=T 仅作历史兼容。exit_armed 表示本圈已锁存分隔带。CSV 为 42 列，新增 IMU 三轴加速度、陀螺仪、偏航角速度及采样状态，条纹停车原因是 9。当前发布构建标识为 `FW=0.38.0`。历史 0.29 发布及 0.28 标识的烧录记录见 CHANGELOG，0.37.0 已完成实车缓存导出，0.38.0 的本地下载未取得校验成功记录。

##### 使用流程

1. 烧录后正常上电。C13有效启动新一趟记录；仅开机/停车预览不产生记录。
2. 每20ms保存一次控制快照（50Hz）。C13手动停车或任何自动保护停车均冻结缓存，额外保存停车瞬间一条，即使该时刻不在20ms采样点上。启动未成功时仍可保留一条失败状态。
3. 停车后保持供电，不复位、不重新烧录、不再按C13。关闭逐飞助手或其他占用串口的软件，连接下载器串口，C12屏幕/图传必须开启。
4. 在项目根目录执行以下命令，COM6换成实际串口，文件名每次换新：

   ```powershell
   python tools/export_steering_log.py --port COM6 --output steering-run-01.csv
   ```

   Python需要已有`pyserial`。串口沿用固件115200、8N1。
5. 脚本显示`Saved ... verified rows`才表示完整成功。Excel/Python可直接读取CSV。

再次C13启动会立即覆盖上一趟记录，不等待导出。断电、复位或烧录会丢失缓存。完成导出不会清空车端记录，同一趟可重复导出。C12关屏不影响记录，但会取消导出；导出中再启动C13不改变启动行为，电脑报告导出中断。

##### 容量与时序

- 专用SDRAM数组恰好1,048,576字节，32字节对齐；每条72字节，容量14,563条，余40字节不用。
- 名义保存最近约291.26秒（约4分51秒）。满后覆盖最旧记录；CSV按时间先后输出，电脑提示覆盖条数。
- PIT原有10ms周期不变；每两个周期留一条，另留启动/停车瞬间。`ms`为控制时钟，不是电脑时间；每约49.7天uint32回绕，采样间隔用无符号差处理。
- 运行期间无日志串口输出、无CSV格式化、无文件写入。主循环仅在收到`LOG`命令且已停车时导出。
- 1MiB指二进制缓存，CSV文本比它大。115200串口导出满缓存通常需要数分钟，实际耗时待硬件测量，脚本总超时600秒、无数据超时20秒。

| servo10 | 最终限幅/限速后的舵机指令角×10；870是87°，不是实测角。普通停机时舵机PWM关闭；原因9条纹锁停时持续输出触发瞬间角度，字段仍非实测角 |

##### 协议与完整性

历史2026-11-05出环偏转尚未实车验收；当前排查对齐S阶段、G编号、N/G/H/U来源、servo10、frame_age_ms和中线有效性。当前没有T计时直行，不把中位指令等同于实车沿直线。

- 请求`LOG\n`；运行时回复`#LOG ERROR RUNNING`，尚无记录回复`#LOG ERROR EMPTY`。关闭C12时不响应导出。
- 起始`#LOG BEGIN session count overwritten FW=0.38.0`，随后CSV表头与数据行。
- 结束`#LOG END session count fnv1a`。FNV-1a 32位覆盖所有数据行原始ASCII字节（含CRLF），不含表头；用于传输差错检测，不是安全签名。
- 使用现有UART中断发送队列，导出期间暂停摄像头图传/示波器输出，不混发二进制图像；屏幕和图像识别仍正常执行。
- 主循环仅在短临界区读取元信息或一条56字节记录。CSV格式化和串口发送均在临界区外。新启动改变session，旧导出以`ABORT RESTART`终止。
- `LOG CANCEL\n`取消当前传输，不清记录、不控制电机。脚本退出时发送此命令。
- 电脑先写`.csv.partial`；条数/会话/校验全部一致才改名为`.csv`。失败保留partial，重试使用新文件名，不覆盖已有文件。开始时可能有残留图像字节，脚本等待BEGIN后才解析CSV。

### 接手修改的顺序

1. 从 `main` 获取当前工程，核对 `version.yml`、三个固件版本输出和环岛开关，再读 SUMMARY 与本文的运行诊断。
