# Wedontcar-Vision-Control

智能车竞赛镜头组 RT1064 固件：MT9V034 图像采集、白色赛道识别、PD 转向与双轮 PI 调速。

当前版本 **0.4.0**（2026-10-21），开发分支 `1021-yubao`，基于 `10-21-medium`。版本与算法变化见 [CHANGELOG](CHANGELOG.md)，接手顺序见 [SUMMARY](SUMMARY.md)，协作规则见 [COLLABORATORS](COLLABORATORS.md)，实车验收清单见 [待测试](待测试.md)。

本版在 `10-21-medium` 基础上改进弯道近端中线、减小远处走向对舵机的前瞻影响，并清理孤立白点与屏幕预览中的游离亮斑。保留远端既有历史和硬件清单；没有进行烧录或本版实车验收。

**默认配置：`RING_FEATURE_ENABLED=0`，仅普通循迹；C14 自动保护已恢复，上电默认关闭。** 保护关闭时允许没有有效图像就按 C13 启动；`READY=0` 不会阻止启动。PWM 上限仍为 2000。不要沿用 v0.3.2 的“C14 无功能”说明。

## 工程与数据流

```text
demo/user/src/       8 个应用 .c 与 2 个被包含的 .inc
demo/user/inc/       板级配置、算法接口、功能开关
demo/mdk/            Keil 工程，目标 nor_sdram_zf_dtcm
demo/iar/            历史 IAR 工程，本版未验证
libraries/           逐飞 RT1064 库、NXP SDK、设备驱动
tools/               主机测试、夹具和图像采样脚本
```

| 文件 | 维护职责 |
| --- | --- |
| `main.c` | 外设初始化、取帧和双翻转、预处理、视觉调用、屏幕与诊断 |
| `img_process.c/.h` | 地面 ROI 自适应阈值、局部补偿、参数平滑与小黑孔处理 |
| `track_vision.c/.h` | 普通赛道边沿/中线、近端路线关联、可选环岛视觉 |
| `track_near_route.inc` | 从近端可见道路播种，约束可连接的白色路线 |
| `ring_360_zore.inc` | 360° 环岛原生尺寸边界与分阶段视觉计算 |
| `track_control.c/.h` | 启停、图像有效性、PD、舵机限速与基础速度 |
| `isr.c` | 10 ms 中断、C12–C15 按键、保护、观测邮箱与最终执行 |
| `pid.c/.h` | 独立双轮 PI、输出限幅与转角差速 |
| `imu_navigation.c/.h` | 100 Hz IMU 采样后的坐标映射、零偏与角速度 |
| `ring_control.c/.h` | 可选 270°/360° 状态、路线选择及特殊动作 |

`.inc` 已由 `track_vision.c` 包含，必须随源码保留，不要再作为独立 C 文件加入工程。`.dist/`、`.reference/` 属于本地历史参考，受 `.gitignore` 排除，克隆本分支不会自动获得。

数据流：CSI 帧 → 独立副本与帧号复核 → 上下/左右双翻转 → 地面预处理 → 普通视觉 → 环岛视觉接口（默认关闭时透传普通观测）→ 邮箱 → 10 ms 控制中断 → PD 与目标轮速 → 双轮 PI → PWM。

## 当前算法

### 图像与路线

- 摄像头配置 376×240、50 帧、曝光 1024；屏幕、图传和算法使用同一双翻转方向。
- `image_track_preprocess_stable()` 只用 `[30%H, 68%H)` 地面区域估计参数和处理图像，区域外不参与阈值统计；替代旧的全图均值加全图 Otsu 主流程，旧工具函数仍保留。
- 预处理使用受限增益、4×3 分块局部补偿、按时间平滑的阈值参数、孤立噪点清理和小黑孔填充。白权重 42%、局部强度 50%、平滑时间常数 25 ms；仅保存参数，不沿用上一帧像素或中线。弱分离图像不会被强行分成黑白两类。
- 普通循迹 ROI 为 `[40%H, 68%H)`，区别于 v0.3.2 的 `[20%H, 68%H)`；以 240 行为例是第 96–162 行（从 0 计数）。底部固定车体遮挡继续排除。
- 路线关联在 `[55%H, 68%H)` 近端寻找种子，再向远端传播；不把断开的远处道路重新当种子。近端关联最大允许缺行 `TRACK_ROUTE_MAX_GAP_ROWS=1`。路线掩码与普通中线的缺行/宽度/连续性判断是不同层次。
- 白段宽度约 6.25%W–80%W、密度至少 75%；双边界与唯一连续分支约束仍在。总行、近端和远端覆盖各需达到 45%。无效帧误差与航向清零，不用虚构中线掩盖丢线。

### 转向与速度

- 普通 PD：`KP=0.020`、`KD=0.0005`；航向权重 `TRACK_HEADING_WEIGHT=1.60`（前版为 2.00，降低提前入弯趋势）；舵机变化率 120°/s（10 ms 最多 1.2°）。
- 舵机右/中/左仍为 75.5° / 87.0° / 98.5°，C30、50 Hz。
- 基础速度低速 120/80、全速 240/160，单位为编码器计数/10 ms。
- 差速改为 `delta = target × 0.4 × tan(转角)`，`SPEED_DIFF_GAIN` 位于 `pid.h`；左右目标为 `target ± delta`，增减限公共目标的 50%。不再使用旧版固定满舵 110%/90% 的说明。
- 双轮 PI 仍为 P=50、I=0.2、D=0，积分限 5000；最终 PWM 范围 0–2000。环岛开启且锁定 360° 动作时使用专用运动输出并关闭普通差速。

### 按键、启动与保护

| 按键 | 功能 | 上电默认 |
| --- | --- | --- |
| C12 | 屏幕与 USB 图传开关 | 开启 |
| C13 | 整车启动/停止；重新启动时清除环岛完成记录 | 停止 |
| C14 | 自动保护总开关 | 关闭（`AUTOMATIC_PROTECTION_DEFAULT=0`） |
| C15 | 低速/全速 | 低速 |

保护开启时，启动要求连续 3 个有效观测且置信度 ≥45；连续 3 帧无效、图像超过 150 ms 未更新、编码器反号、无反馈和异常超速可触发自动停止。保护关闭时这些条件不会自动停车，C13 仍能停止；无效/超时图像期间保持原舵角并降至弯道最低速度。重新开启保护会立即复核已有图像状态。保护只控制停机，视觉计算继续运行。

### 环岛功能开关与维护边界

`demo/user/inc/track_vision.h` 的 `RING_FEATURE_ENABLED` 默认为 0。当前运行不生成环岛候选、不准入 270°/360° 特殊控制，残留环岛状态会清理，普通弯道循迹仍开启。

如需验证环岛，将宏改为 1 后完整重编译；主机编译可用 `-DRING_FEATURE_ENABLED=1`。保留实现包括独立 `[30%, 68%)` 视觉、270° 入口/出口直线参考、360° ZORE 分阶段视觉与原生图像坐标、完成记录与故障处理。360° 不是旧版“累计到 270° 即出环”的实现。开启后必须单独标定；默认关闭版本的通过项不能视为环岛实车验收。

## 编译与调试

1. 安装 Keil MDK 5、Arm Compiler **6.19**（当前 `pCCUsed`），以及 `NXP.MIMXRT1064_DFP.25.09.00`。库与 SDK 已在仓库内。
2. 打开 `demo/mdk/rt1064.uvprojx`，选择 `nor_sdram_zf_dtcm`，执行 Rebuild。本次按源目录 6.19/25.09.00 配置保留；远端原工程为 6.24/26.06.00，参考 main 目录为 6.21，配置差异见 CHANGELOG。
3. 输出在 `demo/mdk/Objects/rt1064.axf`；Objects、Listings、个人 `.uvguix.*` 不提交。IAR 工程需另行验证。
4. 烧录后先确认诊断 `#CAM FW=0.4.0`、`PROTECT` 和按键，再按 [待测试清单](待测试.md) 完成架空与低速测试。本次上传没有执行烧录。

USB 图像与诊断由 C12 同时控制，默认发送冻结的原始灰度图（`CAMERA_SEND_RAW=1`）。屏幕使用处理后的二值图和同帧叠加线；图传原始灰度与二值屏幕不应直接按像素颜色比较。

| 诊断字段 | 含义 |
| --- | --- |
| `CAP/VF/PROC/DISP`、`CFPS/PFPS/DFPS` | 采集/视觉帧号、处理/显示计数和帧率 |
| `MOTOR/PROTECT/FULL`、`READY/STOP` | 运行、保护、速度档位、就绪与停机原因 |
| `TRACK/Q/VR/N/F`、`REJ/NC/AM/DC` | 有效性、置信度、覆盖和拒绝原因 |
| `ERR/HEAD`、`SERVO10/TARGET10` | 误差、航向、舵角×10、目标速度×10 |
| `LSPD/RSPD/LPWM/RPWM` | 两轮反馈与输出 |
| `EXP/THR/BAD`、`IMU/IB/YR10` | 曝光、阈值、无效帧、IMU/零偏与偏航角速度×10 |
| `RT/RS/ENT/PASS/EXT/PATH/RF` | 环岛类型、阶段、入口/出口、路线与故障；环岛默认关闭 |

诊断头中的 `FW=0.4.0` 是固件版本，后面的数值 `FW=` 是历史沿用的 far width（远端宽度）字段；解析时用位置/字段类型区分。

## 接手修改的顺序

1. 从 `10-21-medium` 建个人分支，确认版本与默认开关；源码以本分支为准，不依赖作者 E 盘路径。
2. 先运行预处理、开关和控制测试；记录光照、安装角度、C14 状态、C15 档位与诊断帧。
3. 图像问题改 `img_process.h`，近端关联改 `track_near_route.inc`，普通转向改 `main.h`/`track_control.c`，差速改 `pid.h`；一次只改一组。
4. 环岛开启、工程配置变化和实车结论分别记录，更新版本、固件诊断字符串及四份主文档后提交 PR。
