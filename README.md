# Wedontcar-Vision-Control

智能车竞赛镜头组的完整固件工程：MT9V034 采集赛道图像，提取中线并计算横向偏差，用 PD 控制舵机、PI 控制双轮速度，并通过 IMU 角速度识别环岛。

## 项目背景

本队参加镜头组。底盘、电机和机械结构沿用校内上一组电磁组的方案，但拆除电磁传感器及其信号处理，改用总钻风 MT9V034 120° 摄像头做赛道感知；控制程序在上一组 RT1064 工程的基础上重写为视觉方案。


用户代码按职责拆分：

| 文件 | 职责 |
| --- | --- |
| `main.c` | 初始化外设、主循环取帧、翻转/去噪/二值化、刷屏与串口输出 |
| `isr.c` | 10 ms 控制中断：按键扫描、IMU 采样、控制 tick、电机与舵机输出 |
| `img_process.c` | 3×3 均值去噪、直方图与 Otsu 阈值、二值化 |
| `track_vision.c` | 从二值图提取赛道边界、中线、误差、航向量和环岛候选 |
| `track_control.c` | 启停状态机、PD 转向、速度目标与差速分配 |
| `pid.c` | 双轮速度 PI 的位置式实现与抗饱和 |
| `imu_navigation.c` | 车体轴映射、GY 零偏估计、偏航角速度 |
| `ring_control.c` | 环岛候选确认、方向锁定、转角积分、出口与冷却 |

数据流：CSI 采帧 → 复制并做上下/左右翻转 → 3×3 均值 → Otsu 二值化 → `track_vision_process()` → 结果发布到邮箱 → 10 ms 中断读取最新结果 → `track_control_tick()` 算出舵机角与双轮目标 → 速度 PI → PWM。

## 功能说明（v0.3.2）

### 1. 图像采集与预处理

- 摄像头固定 376×240、50 帧，曝光 1024（`main.c` 的 `CAMERA_TUNING_EXPOSURE`）；
- 每帧先复制到独立缓冲区再处理，避免与 CSI 写缓冲冲突；复制期间如果摄像头已经换帧，直接丢弃这一帧；
- 同一帧号只处理一次，重复帧不会计入“连续有效帧”；
- 复制后先上下翻转、再左右翻转，因为摄像头是反装的；屏幕、USB 图传和算法使用同一方向；
- 去噪用 3×3 整数均值（两行缓存、原地处理），之后做全图直方图 + Otsu，阈值钳位在 1–254；
- 默认把冻结的原始灰度帧发到 USB（`CAMERA_SEND_RAW=1`），屏幕关闭时不发送。

### 2. 赛道识别

- 只处理图像纵向 `[20%, 68%)`：上方过远容易受透视和噪声影响，下方 68% 以外是确认过的车体固定遮挡；
- 逐行找白色连续段，合格条件：宽度在 6.25%W–80%W 之间、段内白色密度 ≥75%、允许不超过 2 像素的黑缝；
- 从近到远只接受与上一行重叠 ≥1/4 的唯一候选；逐行位移不超过 2.1%W，连续缺行不超过 4.2%H；
- 同一行出现两个都符合条件的分支时判为分叉，中线在该行前终止，不拼接、不外推；
- 置信度 = 有效行 / ROI 总行数 ×100；总有效行、近端有效行、远端有效行各自都要 ≥45%，否则整帧判无效；
- 输出包括：横向误差 `error`（约 ±1000，赛道偏右为正）、远近航向量 `heading`（远端向右为正）、近/远平均宽度、宽度增长率、环岛候选与方向；
- 环岛候选要求远端宽度 ≥ 近端 135%、且达到图像宽度的 40%，同时远近中心偏移 ≥ `W/16`；对称张开（例如十字）不再触发。

### 3. 转向控制

- 位置式 PD，误差先滤波，航向量按 1.5 的权重参与，避免弯道里轻微反向的横向误差把方向拉回去；
- 常规参数 `KP=0.020`、`KD=0.0005`，舵机变化率 200 °/s；
- 环岛相关阶段临时切换到 `KP=0.025`、`KD=0.0007`、360 °/s，机械端点不变；
- 舵机输出限制在 75.5°–98.5°，10 ms 周期内最多变化 2°，不会一步打到端点；
- 当前帧无效或图像超时时保持上一拍角度、清掉微分状态，目标速度降到弯道最低值。

### 4. 速度与差速

- 双轮独立位置式 PI：`KP=50`、`KI=0.2`、`KD=0`，积分限幅 5000，输出上限 2000；
- 目标速度按转向严重程度在“直道速度”和“弯道最低速度”之间线性插值，不是简单的弯道开关；
- 低速 120/80、全速 240/160，单位是编码器计数 / 10 ms；
- 满舵时外轮 110%、内轮 90%，只改左右目标分配，不改档位和 PI 参数；
- 最终 PWM 统一限幅在 2000，即满量程的 20%，差速不能绕过这个上限。

### 5. 按键与启停

| 按键 | 短按 | 默认 | 说明 |
| --- | --- | --- | --- |
| C12 | 开关屏幕与 USB 图传 | 开启 | 关闭后停止刷屏和发图，把算力留给算法 |
| C13 | 启动 / 停止 | 停止 | 启动需要连续 3 帧有效赛道；按住上电不会启动 |
| C15 | 低速 / 全速 | 低速 | 只改速度倍率，不改保护、按键和舵机标定 |
| C14 | 无功能 | — | v0.3.2 起不再参与启停或保护 |

- 三个按键都是 30 ms 去抖，长按不连发；
- 启动条件：连续 3 个不同帧号的有效观测，且置信度 ≥45；条件满足后串口 `READY=1`；
- v0.3.2 移除了全部自动停机，丢线、停帧、编码器反号、堵转、超速都不会自动停车，只有 C13 能停；
- 停车时两路 PWM 直接归零，不做主动制动；重新启动必须再按一次 C13。

### 6. IMU 与偏航角速度

- IMU660RB（LSM6DSR），SPI4 10 MHz，`WHO_AM_I=0x6B`；配置为 208 Hz、±8 g、±2000 dps，开启 BDU 和地址自动递增；
- 一次 12 字节突发读取拿到同一批次的陀螺仪和加速度，读取放在 10 ms 控制中断里，固定 100 Hz，不受屏幕和图像处理速度影响；
- 上电静止采集 200 个样本估计 GY 零偏（约 2 秒）；标定期间如果车辆被判定为运行，样本清零重来；
- 车体坐标固定：前进 `-Z`、左侧 `+X`、上方 `-Y`；
- 偏航角速度 `yaw_rate_dps = -(gyro_y - bias) × 0.07`，绝对值小于 1.5 °/s 时置零；内部约定左转为正。

### 7. 环岛状态机

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `R0 IDLE` | 未发现环岛，或车辆停止 | 停车立即复位 |
| `R1 CANDIDATE` | 收到视觉候选 | 远端显著张开且中心偏移 ≥ `W/16` |
| `R2 ENTERING` | 候选已确认，等待实际偏航 | 连续 3 帧候选 |
| `R3 INSIDE` | 已确认进入环岛 | 同方向角速度 ≥12 °/s 连续 5 个 10 ms 周期 |
| `R4 EXITING` | 开始出环 | 净转角 ≥270° |
| `R5 COOLDOWN` | 已退出，抑制重复触发 | 出口满足条件，或转角到 420° |

关键规则：

- 方向只由实测角速度决定，视觉给出的左右提示不可靠时会直接反转；入环首个弯与环内转向相反时，在累计 45° 以内允许重新锁定方向；
- 转角按带符号净转角积分，反方向会抵消，下限为 0，避免左右摆动被累成一整圈；
- `CANDIDATE` 和 `ENTERING` 阶段不接管转向，车辆沿白色赛道中线自然开到入口；
- `INSIDE` 阶段也不强制打舵，仍由视觉中线控制；只有 `EXITING` 会强制向环外打舵；
- 出口需要至少 150 ms 且连续 2 帧普通赛道；累计到 420° 直接退出，防止卡死在环里；
- 接近超时 1500 ms、环内超时 12000 ms、出口超时 2500 ms，超时只撤销特殊转向，不停车；
- 陀螺仪失效时立即退出环岛特殊控制并进入冷却，视觉循迹继续；
- 冷却 3000 ms，冷却结束前同一形态不会再次触发。

### 8. 诊断输出

屏幕把 376×240 的二值图缩放到 125×100 显示，红色点是算法判定的左右边沿，蓝色点是中线，只画在有效行上。文字区三行：

- 第一行 `E:%4d H:%4d`：横向误差、远近航向量；
- 第二行 `Q%3u R%u C%u Y%3d`：置信度、环岛状态编号、当前帧候选、累计转角；
- 第三行：`ENC WARN:n` 编码器反号、`CAM WARN` 启动后无有效图像、`IMU WARN` IMU 未就绪、`RUN LOW` / `RUN FULL` 运行中、`C13 START` 已停机。

## 使用指南

### 1. 环境准备

- Keil MDK 5，Arm Compiler 6.21（工程已固定，换编译器版本可能报错）；
- 逐飞双模 DAP 调试器及其驱动，工程里已选择 CMSIS-DAP 下载方式；
- 跑主机测试需要 gcc（本机用 gcc 15.2 验证）；
- 仓库已内含逐飞 RT1064 库和 NXP SDK，工程使用相对路径，不需要额外安装。

### 2. 编译

1. 打开 `demo/mdk/rt1064.uvprojx`；
2. 目标选择 `nor_sdram_zf_dtcm`；
3. 执行 Build（F7）；
4. 产物为 `demo/mdk/Objects/rt1064.axf`，构建日志默认也在同一目录。

### 3. 烧录

1. CMSIS-DAP 接 SWD 和 USB；
2. 确认 Options → Debug 里选中的是双模 DAP 的 CMSIS-DAP 模式；
3. 执行 Download（F8），等待 `Erase Done / Programming Done / Verify OK`；
4. 烧录完成后程序自动运行，屏幕先白屏，随后显示二值图和诊断行。

历史日志末尾偶尔出现 `RDDI-DAP Error`，它发生在校验通过和程序启动之后，不影响本次烧录结果，但需要在车上确认程序确实在跑。

### 4. 上电与启动

1. 确认驱动板使能开关在 ON、电池电量足够（3S 满电 12.6 V），再给车上电；
2. 把车放平、保持静止，等待约 2 秒让 IMU 完成零偏；接 USB 时确认 `IB=1`（串口约 8 秒才刷新一包，需要等一会）；
3. 把车放到赛道中央，让摄像头能完整看到近端和远端赛道；
4. 确认 `READY=1` 后按 C13 启动；
5. 先保持 C15 低速档试跑，确认直道和弯道方向正确；
6. 需要停车时按 C13；出现任何异常也直接按 C13；
7. 要关屏或减少 USB 干扰时按 C12（长按不生效，是短按切换）。

### 5. 按键操作

| 操作 | 结果 |
| --- | --- |
| 短按 C13（已停机且 `READY=1`） | 启动，舵机与电机开始输出 |
| 短按 C13（运行中） | 立即停车，PWM 归零，PID 历史清空 |
| 短按 C13（未 ready） | 不启动，屏幕仍是 `C13 START` |
| 短按 C15 | 低速 ↔ 全速切换 |
| 短按 C12 | 屏幕与图传开 ↔ 关 |
| 按住任意键上电 | 该按键本次上电不生效 |

### 6. 屏幕显示

- 图像区：二值图 + 红色边沿 + 蓝色中线，可直接看出赛道识别是否跟丢；
- 第一行看误差和航向量是否连续，突变通常意味着某帧识别异常；
- 第二行 `R` 是环岛状态，正常赛道应长期为 0；`C` 是当前帧候选，偶尔为 1 属正常；
- 第三行用来判断为什么不动：`CAM WARN` 优先查摄像头，`IMU WARN` 查 SPI4 接线。

### 7. 串口诊断

USB 虚拟串口，115200、8N1。每个数据包 = 一行 `#CAM ...` 诊断文本 + 12 字节图像头 + 376×240 灰度图，一帧约 90 KB，所以 115200 下一包要 8 秒左右，刷新很慢，只适合抽查。串口输出依附 C12：关屏后不再发送。

| 字段 | 含义 |
| --- | --- |
| `T/CAP/VF/PROC/DISP` | 毫秒时间戳、采集帧号、视觉帧号、已处理帧数、已显示帧数 |
| `CFPS/PFPS/DFPS` | 采集、处理、显示帧率 |
| `IO/MOTOR/MFAULT/PROTECT/FULL/STATUS` | IO 状态、运行标志、编码器反号掩码、保护标志（v0.3.2 恒 0）、全速标志、图像状态 |
| `TRACK/Q/VR/N/F` | 赛道有效标志、置信度、有效行/ROI 行、近端与远端有效行 |
| `NW/FW/WG` | 近端宽度、远端宽度、宽度增长率 |
| `RC/RD` | 本帧环岛候选、视觉方向提示 |
| `REJ/NC/AM/DC` | 拒绝位、无候选行、歧义行、断连行 |
| `ERR/HEAD` | 横向误差、航向量 |
| `READY/STOP` | 是否满足启动条件、最近一次停机原因 |
| `SERVO10/TARGET10` | 舵机角度 ×10、目标速度 ×10 |
| `LSPD/RSPD/LPWM/RPWM` | 左右轮实测速度与 PWM 指令 |
| `EXP/THR/BAD` | 曝光值、本帧二值化阈值、累计无效帧数 |
| `IMU/ID/IS/IB/IBS` | IMU 状态、芯片 ID、累计样本、零偏是否完成、零偏样本数 |
| `AF/AL/AU/GY/YR10` | 车体前/左/上加速度、GY 原始值、偏航角速度 ×10 |
| `RS/RDIR/RY10` | 环岛状态、确认方向、累计转角 ×10 |

注意：固件里的版本串仍是 `FW=0.3.1`，v0.3.2 没有同步修改，按串口判断版本时不要被它误导。

### 8. 标定与调参

改参数 = 改宏 → 重新编译 → 烧录 → 按下面的方法验证，不要一次改多项。

| 目标 | 位置 | 方法 |
| --- | --- | --- |
| 舵机中值与端点 | `main.h` 的 `SERVO_MOTOR_CENTER` / `_L_MAX` / `_R_MAX` | 打开 `SERVO_CENTER_TEST_MODE`，用 C12/C15 每次 0.5° 调整，找到机械正中后记录 |
| 转向 PD 与舵机速率 | `main.h` 的 `TRACK_STEER_KP/KD`、`TRACK_SERVO_RATE_DEG_S` | 先在直道确认不画龙，再逐步提高弯道响应 |
| 环岛方向环 | `main.h` 的 `TRACK_RING_*` | 与常规 PD 分开调，避免互相掩盖 |
| 速度目标与差速 | `track_control.h` 的 `TRACK_SPEED_*`、`TRACK_DIFF_GAIN` | 先低速跑顺，再整体提高，差速过大容易在弯心甩尾 |
| 丢线与停帧阈值 | `track_control.h` 的 `TRACK_LOST_STOP_FRAMES`、`TRACK_STALE_MS` | 当前版本只影响内部状态，不再触发停机 |
| 环岛阈值 | `ring_control.h` | 先停车采样入口处的 `NW/FW/WG/RC/RD`，再决定确认帧数和出口角度 |
| 视觉 ROI 与候选 | `track_vision.h` | 改 ROI 会同时影响宽度统计和环岛候选，改完必须重跑视觉测试 |
| 速度 PI | `pid.c` 的 `speed_KP/KI/KD`、`IMAX`、`OUTMAX` | 先确认方向正确，再调积分；`OUTMAX` 不要超过 2000 |
| 摄像头曝光 | `main.c` 的 `CAMERA_TUNING_EXPOSURE` | 光照变化大时先调曝光，再调二值化 |

### 10. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 屏幕全黑 | 按过 C12 关屏、摄像头排线松动、曝光为 0 | 再按 C12；检查 CSI 排线与供电；恢复屏幕后看 `EXP` |
| 屏幕先白屏后无图 | 摄像头初始化失败 | 看串口 `STATUS`，检查 CSI 引脚与摄像头供电 |
| 屏幕显示 `IMU660RB ERROR` 或 `ID` 不是 `6B` | SPI4 接线错误或器件未就绪 | 检查 `C20`–`C23` 与 3.3V 供电 |
| 上电后整车毫无反应 | 驱动板使能开关在 OFF，或电池电量不足 | 把使能开关拨到 ON，测量电池电压 |
| 按 C13 没反应 | `READY=0`，没有连续 3 帧有效赛道 | 把车放到赛道中央，看 `TRACK/Q` 和屏幕二值图 |
| 车往反方向走 | 电机方向或编码器符号接反 | 改 `main.h` 的 `MOTOR1/2_FORWARD_DIR_LEVEL` 或 `ENCODER_1/2_FORWARD_SIGN` |
| 直道画龙 | 舵机中值不准，或 PD 的 D 过大 | 重新标定中值，再降 `KD` |
| 弯道冲出去 | 舵机速率或 KP 不足、速度过高 | 先降速，再逐步提高 `TRACK_SERVO_RATE_DEG_S` 与 KP |
| 串口没有输出 | 波特率不对、USB 线只供电 | 用 115200，换数据线 |
| 图像有白条 | USB 供电噪声 | 断开 USB 运行，或用独立供电 |
| 烧录失败 | 双模 DAP 未识别、目标供电不足 | 重新插拔、检查 SWD 接线与供电 |

## 目录说明

- `demo/`：当前 RT1064 应用工程，含用户代码、Keil 工程和 IAR 工程；
- `demo/user/src`、`demo/user/inc`：全部用户代码，新增模块要同时加进 Keil 工程；
- `libraries/`：逐飞库与 NXP SDK，一般不改；
- `tools/`：10 组主机侧测试，每组一个 `.c` 加一个 `.ps1` 运行脚本；
- 根目录文档：`README.md`（本文件）、`SUMMARY.md`（项目摘要）、`CHANGELOG.md`（版本记录）、`COLLABORATORS.md`（分支与文档规范）、`version.yml`（当前版本元信息）。

## 注意事项

- 舵机供电来自主板可调稳压，上电前确认档位不超过 S-U400 的 7.4 V 上限；
- RS380 额定 7.2 V，而电池为 11.1 V，固件用 PWM 2000（20%）上限压制输出，不要为提速解除该限制；
- 舵机端点、速度目标、PID 和视觉阈值都是按本车标定的，换车或换机械结构后必须重新标定；
- 不同主板的时钟、引脚和外设配置不同，别人板子上的例程不能未经移植直接编译到 RT1064；
- IAR 工程未同步 v0.3.2 的源码改动，用 IAR 打开前需要先补齐工程文件列表；
- 所有改动走个人分支 + PR，不要直接修改 `main`。
