# Wedontcar-Vision-Control

智能车竞赛镜头组 RT1064 固件：MT9V034 图像采集、白色赛道识别、PD 转向与双轮 PI 调速。

当前版本 **0.6.1**（2026-10-25），当前工作分支 `1025-ainepadma`，直接基于合并主线 `1c60837` 和本地0.5.1启用改动。版本与算法变化见 [CHANGELOG](CHANGELOG.md)，接手顺序见 [SUMMARY](SUMMARY.md)，协作规则见 [COLLABORATORS](COLLABORATORS.md)，实车验收清单见 [待测试](待测试.md)。

> **智能体协作强制要求：** 每次与智能体的对话只要改动了源码、头文件、工程配置、测试或脚本，就必须在该次对话内同步更新版本号和 `CHANGELOG.md`。版本递增级别与例外情况以 [CHANGELOG 的版本规则](CHANGELOG.md#智能体代码操作的版本规则) 为准，不得把版本同步推迟到下一次对话。

本版将环岛控制改为角点序列与局部边界修补：270°按左右角点数量执行“各一个时延长、各两个时同侧连线”，入口和出口各执行一次；360°按A→B→A→B四次事件选边，第1/3次左右镜像复用，第2/4次选边不同。同一360°角点接近车辆时会由远处斜锐角连续变化为近似直角，分类保留主臂方向约束并容忍支臂在横向附近的小幅量化抖动；环岛类型仍由角点数量与状态序列区分。环岛路径交给现有PD控制，不再由旧ZORE专用转向覆盖输出。摄像头与普通循迹参数沿用当前基线；2026-10-25 21:57已烧录并通过COM6核实车端运行0.6.1且电机停机。

**版本标识状态：** `version.yml`、固件诊断标签和车端COM6回报均为0.6.1；YAML提交字段对应本版提交标题，发布分支为`1025-ainepadma`。0.6.1已修复实拍透视下同一360°锐角在A/NONE之间抖动的问题，16/16主机测试和Keil完整编译通过，已烧录但尚未完成360°连续接近与行驶验收。

**默认配置：`RING_FEATURE_ENABLED=1`，启用角点环岛链路；C14 自动保护上电默认关闭。** 保护关闭时允许没有有效图像就按 C13 启动；`READY=0` 不会阻止启动。PWM 上限仍为2000（20%）。离线合成图测试和编译不能证明实际赛道识别已通过。

## 工程与数据流

```text
demo/user/src/       应用源码、角点几何与保留的历史视觉模块
demo/user/inc/       板级配置、算法接口、功能开关
demo/mdk/            Keil 工程，目标 nor_sdram_zf_dtcm
demo/iar/            历史 IAR 工程，本版未验证
libraries/           逐飞 RT1064 库、NXP SDK、设备驱动
tools/               主机测试、夹具和图像采样脚本
```

| 文件 | 维护职责 |
| --- | --- |
| `main.c` | 外设初始化、取帧和双翻转、预处理、视觉调用、屏幕与诊断 |
| `img_process.c/.h` | 地面 ROI 自适应阈值、局部补偿、参数平滑与小黑孔处理 |
| `track_vision.c/.h` | 普通赛道边沿/中线、近端路线关联、可选环岛视觉 |
| `track_near_route.inc` | 从近端可见道路播种，约束可连接的白色路线 |
| `ring_corner.c/.h` | 角点数量、有方向的两臂、左右镜像与局部边界修补候选 |
| `ring_360_zore.inc` | 历史360°视觉实现，0.6.0运行链不再采用 |
| `track_control.c/.h` | 启停、图像有效性、PD、舵机限速与基础速度 |
| `isr.c` | 10 ms 中断、C12–C15 按键、保护、观测邮箱与最终执行 |
| `pid.c/.h` | 独立双轮 PI、输出限幅与转角差速 |
| `imu_navigation.c/.h` | 100 Hz IMU 采样后的坐标映射、零偏与角速度 |
| `ring_control.c/.h` | 可选 270°/360° 状态、路线选择及特殊动作 |

`track_near_route.inc` 由视觉源码包含，不应作为独立C文件加入工程；`ring_corner.c` 是独立编译模块。旧ZORE源码保留用于历史对照，不应重新接回控制输出。`.dist/`、`.reference/` 属于本地历史参考，受 `.gitignore` 排除，克隆本分支不会自动获得。

数据流：CSI帧 → 独立副本与帧号复核 → 上下/左右双翻转 → 地面预处理 → 普通视觉与角点几何 → 同帧候选路径邮箱 → 10 ms中断内环岛状态选择 → 现有PD与舵机限速 → 目标轮速与双轮PI → PWM。像素扫描和线段几何在主循环完成，中断消费结果，不扫描图像。

## 当前算法

### 图像与路线

- 摄像头配置 376×240、50 帧；`MT9V03X_AUTO_EXP_DEF=0`、`CAMERA_TUNING_EXPOSURE=1024U`，保持手动曝光。`MT9V03X_GAIN_DEF` 从 32 调至 64（驱动标注范围上限），`CAMERA_TUNING_AUTO_BLACK_LEVEL=1U`，初始化在设置曝光后写寄存器 `0x47=0x0080`。该写入返回值未检查，是否生效需硬件确认；不能把自动黑电平配置等同于自动曝光。屏幕、图传和算法使用同一双翻转方向。
- `image_track_preprocess_stable()` 只用 `[30%H, 68%H)` 地面区域估计参数和处理图像，区域外不参与阈值统计；替代旧的全图均值加全图 Otsu 主流程，旧工具函数仍保留。
- 预处理使用受限增益、4×3 分块局部补偿、按时间平滑的阈值参数、孤立噪点清理和小黑孔填充。白权重 42%、局部强度 50%、平滑时间常数 25 ms；仅保存参数，不沿用上一帧像素或中线。弱分离图像不会被强行分成黑白两类。
- 预览过滤不再清零 `[0, 30%H)` 上方区域（240 行时为第 0–71 行），保留输入二值图；地面 `[30%H, 68%H)` 仍隐藏未连到近端赛道的白区，底部区域保留。预览在本帧视觉计算和结果发布之后执行，不改变控制输入或提前冻结的原始灰度图。
- 普通循迹 ROI 为 `[40%H, 68%H)`，区别于 v0.3.2 的 `[20%H, 68%H)`；以 240 行为例是第 96–162 行（从 0 计数）。底部固定车体遮挡继续排除。
- 路线关联在 `[55%H, 68%H)` 近端寻找种子，再向远端传播；不把断开的远处道路重新当种子。近端关联最大允许缺行 `TRACK_ROUTE_MAX_GAP_ROWS=1`。路线掩码与普通中线的缺行/宽度/连续性判断是不同层次。
- 白段宽度约 6.25%W–80%W、密度至少 75%；双边界与唯一连续分支约束仍在。总行、近端和远端覆盖各需达到 45%。无效帧误差与航向清零，不用虚构中线掩盖丢线。

### 转向与速度

- 普通 PD：`KP=0.020`、`KD=0.0005`；航向权重 `TRACK_HEADING_WEIGHT=1.60`（前版为 2.00，降低提前入弯趋势）；舵机变化率 120°/s（10 ms 最多 1.2°）。
- 舵机右/中/左仍为 75.5° / 87.0° / 98.5°，C30、50 Hz。
- 基础速度低速 120/80、全速 240/160，单位为编码器计数/10 ms。
- 差速改为 `delta = target × 0.4 × tan(转角)`，`SPEED_DIFF_GAIN` 位于 `pid.h`；左右目标为 `target ± delta`，增减限公共目标的 50%。不再使用旧版固定满舵 110%/90% 的说明。
- 双轮 PI 仍为 P=50、I=0.2、D=0，积分限5000；最终PWM范围0–2000。锁定360°动作时暂沿用关闭普通差速的既有策略；转向改用所选边界路径进入普通PD，不再调用旧360°专用运动输出。

### 按键、启动与保护

| 按键 | 功能 | 上电默认 |
| --- | --- | --- |
| C12 | 屏幕与 USB 图传开关 | 开启 |
| C13 | 整车启动/停止；重新启动时清除环岛完成记录 | 停止 |
| C14 | 自动保护总开关 | 关闭（`AUTOMATIC_PROTECTION_DEFAULT=0`） |
| C15 | 低速/全速 | 低速 |

保护开启时，启动要求连续 3 个有效观测且置信度 ≥45；连续 3 帧无效、图像超过 150 ms 未更新、编码器反号、无反馈和异常超速可触发自动停止。保护关闭时这些条件不会自动停车，C13 仍能停止；无效/超时图像期间保持原舵角并降至弯道最低速度。重新开启保护会立即复核已有图像状态。保护只控制停机，视觉计算继续运行。

### 环岛功能开关与维护边界

`demo/user/inc/track_vision.h` 的 `RING_FEATURE_ENABLED` 当前为1。角点几何使用原生、已经双翻转的图像和 `[30%, 68%)` 环岛区域，候选路径在 `[40%, 68%)` 形成，普通循迹ROI保持不变。角点检测需要完整的局部支持窗口，实际可检测顶点范围小于搜索ROI：240行图像目前约为第89–145行（从0计数）。这个窗口是否能连续看见实际路口的各个角点仍需实车确认。分类主要看左右目标数量与变化序列，不用“像素夹角接近90°”作为270°/360°分界。

| 类型/事件 | 观测 | 补线规则 |
| --- | --- | --- |
| 270°入口、出口预补线 | 左右各一个有效角点目标 | 沿左右可靠纵向边向前延长，提前封住侧向缺口 |
| 270°入口、出口连接 | 左右各两个有效角点目标 | 左侧近远角相连、右侧近远角相连；不横连左右角 |
| 360°第1/3次 | A类：主臂朝后，另一臂与前向成钝角 | 主臂反向延长；第1/3次使用同一规则，左右镜像还原 |
| 360°第2次 | B类：主臂朝前，另一臂与前向成锐角 | 斜臂反向延长，引导入弯 |
| 360°第4次 | B类，与第2次外观相同 | 朝前主臂反向延长，引导出环 |

A/B中的锐角、钝角指真实轮廓臂与车辆前向的关系，不能用手机照片的上方代替车载坐标。目标必须有空间分离与边缘支持；同一角的锯齿不能重复计数。连续多帧确认、通过确认和状态历史避免把持续可见的入口重复算成出口。补线只影响局部虚拟边界，不修改输入二值图；中线由修补边界生成，不把补线直接当中线。

B2补斜边后，会沿选中的支臂位置在原二值图寻找真实白段边界，不重新配回普通主街的raw边。支路离开画面时，可用连续有效段估计走向，但仍要求路径覆盖、近端支撑和实际补线有效。B2路径不足时明确拒绝，不借用几何上可能仍有效的B4主边路径；否则会把“入弯”错误替换成“出环”。

270°在入口与出口各经历一次“各一个→各两个”；通过路口并恢复真实道路后才允许下一次。环内再次看见有效1/1出口候选时，先采用本帧的纵向延长候选维持通道，再以连续3帧确认记录退出事件，不能为等待确认而让普通寻线跨入侧口。

360°消费A→B→A→B事件，角点换侧不等于行驶方向改变。48%H动作门槛仅约束首次A1；后续事件按期望类别、独立目标、实际运动、连续3帧与有效路径确认，不再给B2/A3/B4重复附加同一行号门槛。B2还要求A1已经通过，或A1已到达可检近端附近，避免A1与远处B同时可见时提前入环；A3要求出现在A1的对侧。通过门槛为本帧 `detector_near_row - max(2, rows×0.02)`：240行图像约140行，最后可检行约145行；不要求必须等到145行，更不使用不可检测的151行。

IMU与编码器用于运动信息及辅助通过判断，不按累计270°或360°强制完成。动作区、角点支持长度和置信度仍须在实际赛道标定。

诊断头中的首个 `FW=0.6.1` 是当前源码及已烧录车端固件版本。后面的数值 `FW=` 是历史沿用的far width（远端宽度）字段，解析时用位置和字段类型区分。

屏幕第二行显示 `L/R/S/G`。270°的S=1/2/3/4/5分别为入口延长、入口连接、环内、出口延长、出口连接；360°的S=1/2/3/4分别为A1、B2斜边、A3、B4主边。G=0表示无补线，1/2为270°延长/连接，3/4为左/右A主边，5/6为左/右B斜边，7/8为左/右B主边。

停车时显示 `PREVIEW STOP` 与 `P` 前缀，表示几何候选预览，不代表运行状态已经消费事件。运行时仅在路径来源帧与当前图像一致、且不是HOLD时绘制采用的补线；应同时对照 `VF/CVF/CGF`。`H`前缀明确表示短时保持的历史路径，不把旧补线叠到新图；`?`表示控制消费帧与图像帧不匹配。普通环内循迹阶段可显示同帧普通蓝线。红色为真实边界，黄色为虚拟边界，蓝色为有效中线点及连续有效段，无效行不强行跨接；角点附A/B或未知标记。

首轮参数集中在 `ring_corner.h`：连续确认3帧、清除确认3帧、首次A1动作起点48%H、最低候选质量55、有效路径短时保持120 ms、辅助前进计数20。前进计数不是厘米；这些是初始软件参数，实际触发距离与镜头安装关系须实测，不能仅凭手机示意图认定合适。

## 接手修改的顺序

1. 当前0.6.1修改位于 `1025-ainepadma`，基于主线 `1c60837` 与本地0.5.1启用改动；接手时先核对工作区和 `version.yml`。
