| 原因 | 编号 | 当前解释 |
| --- | --- | --- |
| NONE / MANUAL / NOT_READY | 0 / 1 / 2 | 无故障、手动停止、保护开启时未就绪 |
| LOST / STALE | 3 / 4 | 连续失效或图像过期；受 C14 视觉保护开关控制 |
| ENCODER / NO_FEEDBACK / OVERSPEED | 5 / 6 / 7 | 编码器反号、无反馈、超速，独立于 C14 |
| RING | 8 | 环岛超时 / 失效保护 |
| STRIPE | 9 | 七条纹主动锁停，复位清除，C13 不能解除 |

## 已查清与尚未确认

当前 AUTOMATIC_PROTECTION_DEFAULT=0U 确实关闭视觉丢线、停帧、未就绪启动限制以及环岛故障停车；C14 仍能在运行时重新开启这些限制。

|---|---|---|

## 本次代码修改

- 加入自动停车瞬间快照：原因、轮号、保护状态、两轮计数、上一周期目标及PWM、时间与事件编号。数据在清零PWM前记录，C13重启不擦除，下一次自动停车更新；下电重启后清空，不写Flash。

- 修复已有诊断错误：TRACK_STOP_RING=8此前被合法原因范围排除，环岛故障会误记成手动停车；现在保留正确原因8。该项只纠正原因分类。
- 没有关闭另外三项保护，没有修改它们的阈值；视觉算法、运动控制计算、PID、C15临时+10按键保留。未修改用户当前调好的速度与转向参数。

验证：tools/test_stop_diagnostics.py 的实际ISR条件复现与快照保留测试通过；控制器完整主机回归通过；Keil固件0错误0警告。原控制测试将120/90写死，本轮改为核对当前速度宏及范围，避免用户合法调速导致测试误报。尚未烧录、未做车辆现场测量。

## 1.00 与0.35怎么调

位置：demo/user/src/track_control.c，TRACK_HEADING_WEIGHT 与 TRACK_APPROACH_HEADING_WEIGHT。以下解释用户提问中的1.00/0.35；打包前检测到用户已自行调整为0.80/0.20，保留这些调参，没有回退。

- 它们不相乘。在近处几何有效时，权重=0.35+aligned×(1.00-0.35)，aligned在0～1之间。普通道路近处直、远处弯时接近0.35；同向弯进入近处后逐渐升至1.00。近处与远处反向时不提升到高权重。
- 无有效近处几何或正在使用环岛补线时，使用1.00。单改0.35通常不能改变环岛补线转向。它们改变航向信息的权重，不改变摄像头视野距离，也不直接改变图像补线。
- 固定车速，每次只改一个量。环岛补线提前转，可先1.00→0.80，再视效果试0.60；普通道路提前转，可先保留1.00，将0.35→0.25。高权重降低也会影响弯中的响应，不保证所有偏早都来自航向项，横向偏差仍参与控制。
- KP=0.030控制整体转向响应，时机正常但转不足才试0.032；若已经到端点则加KP不能增大最大角。变化速度180限制舵机命令每秒最多变化180度，10ms约1.8度；目标正确但响应慢才试200。舵机命令角不是车轮实际转角。
- 中位87.0和端点98.5/75.5属于机械标定，先保持现值；不能用偏移中位补偿错误视觉中线。左端点远离中位、右端点远离中位会扩大对应命令范围，必须按实际机械行程标定。

## 分辨率与帧率

摄像头与识别当前304×154，配置采集50FPS，实际值以日志CFPS为准；屏幕125×100且刷新间隔100ms，即约10FPS。PFPS为实际处理帧率，DFPS为显示帧率。屏幕流畅度不能直接代表识别帧率。

- 采集像素：libraries/zf_device/zf_device_mt9v03x.h 的MT9V03X_W/H；采集FPS配置同文件MT9V03X_FPS_DEF。
- 显示尺寸：demo/user/src/main.c 的TRACK_DISPLAY_WIDTH/HEIGHT；刷新间隔SCREEN_FRAME_PERIOD_MS。将100改50仅把显示频率上限改为20FPS，可能占用更多处理时间，不等于识别提高到20FPS。
- 提高像素数通常增加处理耗时。当前驱动是双缓冲，并有裁剪、binning、图传/处理缓冲等约束，不能直接将宽高填至传感器上限。修改前需核对视野、裁剪偏移、链接内存与算法实测。当前没有改分辨率或帧率配置。
- 先比较CFPS/PFPS/DFPS定位瓶颈；C12关闭显示与图传后的PFPS可用于比较显示/通信负担。没有板上读数时不能断定低帧率由哪段耗时造成。
