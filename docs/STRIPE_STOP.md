# 七条黑条到位停车

本功能已接入 `demo/mdk/rt1064.uvprojx`，代码在 `demo/user`。

## 行为

- 可靠二值帧连续3帧识别完整七条黑条后准备；准备本身不修改循迹或速度。
- 条纹大小与位置同时到位，再连续2个新摄像头帧确认，锁定停车。
- 默认到位：条纹下沿达到有效摄像头画面高度的92%，条纹高度至少28%。当前154行图像对应下沿行号至少141（0起算），高度至少44行。
- 接近阶段允许成组5/6条参与判断，但不能用5/6条首次进入准备状态。检测要求白色包围的内部黑条、相近宽度和间隙、跨行连续性；横向整块黑带、单行噪点、规则8条不能当作完整七条。
- 检测直接读取上下左右翻转后的可靠二值图，位于调试画线之前；不依赖普通循迹 `valid`。不可靠帧不会贡献准备、到位或驶离票数。
- 到位停车不受C14开关影响。停止原因 `TRACK_STOP_STRIPE` 为9，屏幕最近停车显示 `LAST STRIPE`，既有日志中的停车原因也会记录9。
- 停车通过既有控制器锁停，10ms控制中断清零速度目标、两路PWM与PID历史，停机期间持续维持零输出。这里沿用零驱动停车，**不是主动电机制动**，实车会有惯性滑行。
- 屏幕运行状态：`STRIPE ARMED` 表示准备，`STRIPE LEAVE` 表示重启驶离当前标记。
- C13重新启动后，对已经停车/准备的当前标记或近处标记暂时旁路；行驶中连续12个可靠无标记帧后恢复检测下一组。静止预览、摄像头异常不能解除旁路。首次在远处看到标记时启动，不会因此跳过远处标记。
- 仅新摄像头观测累计票数；环岛控制重复刷新、重复时间戳和超过150ms的旧观测不能凑够确认帧。
- 舵机中值标定和架空速度调试模式不执行条纹停车，正常赛道模式执行。

## 调整与实车核对

参数集中在 `demo/user/inc/track_stripe.h`：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `TRACK_STRIPE_BOTTOM_PERCENT` | 92 | 越大越接近画面底部才停车 |
| `TRACK_STRIPE_HEIGHT_PERCENT` | 28 | 越大要求条纹越长才停车 |
| `TRACK_STRIPE_ARM_FRAMES` | 3 | 首次完整七条确认帧数 |
| `TRACK_STRIPE_NEAR_FRAMES` | 2 | 准备后的到位确认帧数 |
| `TRACK_STRIPE_CLEAR_FRAMES` | 12 | 重启后驶离当前标记确认帧数 |

先手推核对P1/P2/P3只显示准备、P4出现条纹停车，再以低速核对实际停稳点。过早停车可增大底部百分比；过晚可适当减小，且需计入两帧确认耗时和车辆惯性。修改后重新编译。

LCD翻拍不能给出准确的物理停车距离。对用户P1～P4照片裁出赛道区域、缩放到304×154，并用灰度阈值100/130做近似回放：四张均识别成组七条；P1～P3 `near=0`、P4 `near=1`。这不是原始相机数据，也没有覆盖固件完整灰度预处理；阈值160回放存在漏检，须以真实二值帧/光照确认稳定性。

## 验证

运行 `python tools/test_track_stripe.py`，需要PATH内有gcc。包括检测器合成场景、缺条、假目标、重复/旧帧、锁停、重启驶离，以及从当前 `isr.c` 抽取实际条纹处理和PWM清零代码的主机测试。

另运行普通控制 `tools/test_track_control.ps1` 和停车诊断 `python tools/test_stop_diagnostics.py`。Keil目标仍为 `nor_sdram_zf_dtcm`。
